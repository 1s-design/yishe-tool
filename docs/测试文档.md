## 0. 一句话说明

设计工具的 AI 生产能力**跑在浏览器里**。测试的本质是：**让设计端在线 → 通过 MCP 下命令 → 看产出是否符合规约**。

## 1. 前置准备（必做）

### 1.1 起服务

```bash
# 后端
cd /Users/jackie/workspace/design-server && npm run start:dev      # :1520

# 前端
cd /Users/jackie/workspace/1s && npm run dev                        # :1522
```

### 1.2 打开设计端并登录（关键）

浏览器打开 `http://localhost:1522/#/design`，用账号 jackie 登录（测试 token 见 `1s/tools/.test-token`）。

> ⚠️ **用 Playwright 自动化时**：`open` 命令每次新建浏览器上下文，localStorage 会丢。必须先注入 token 再**页面内** reload：
> ```bash
> TOKEN=$(cat /Users/jackie/workspace/1s/tools/.test-token)
> "$PWCLI" eval "(localStorage.setItem('token','$TOKEN'), location.reload(), 'ok')"
> ```

### 1.3 确认设计端在线（否则一切命令都会失败）

```bash
TOKEN=$(cat /Users/jackie/workspace/1s/tools/.test-token)
curl -s -X POST http://127.0.0.1:1520/api/ai-assistant/tools/execute \
  -H "Authorization: Bearer $TOKEN" -H "Content-Type: application/json" \
  -d '{"tool":"system.design_tool.query_design_tools","input":{"onlineOnly":true}}'
```

期望：`onlineCount >= 1`，记下 `clientId`（后续所有命令都要用）。

### 1.4 一个设计端同一时间只能跑一个批量任务

新任务会被拒：`当前设计实例正在执行其他自动制作任务`。
→ 先等前一个跑完，或换另一个在线 clientId。**并发靠多开设计端，不靠重复下单。**

## 3. 分链路测试用例

### T-灵感（纯文字灵感）

```bash
node tools/run-inspiration-produce.mjs 4 2 1 "3000x1376:长款,2400x2400:1:1"
```

| 验收点 | 标准 |
|---|---|
| 尺寸 | 与请求的 sizeSpec 完全一致 |
| 主文案居中 | 几何中心落在 (50%,50%) 附近（±3%） |
| 文字完整 | 无截断、无溢出画布 |
| 字号 | 主文案单行 ≤ 画布高 26% |
| 背景 | 至少三层（渐变 + 肌理 + 具象元素） |
| 落库 | 数据库有记录 + URL 可访问 |
| 回写 | `design_inspiration.produced_count` 递增、`status=done` |

### T-带图灵感（视觉链路，v0.0.82 重点）

用带图灵感下单，例如「鼠标垫印花」`7700ff58-4fa9-4ec9-8b84-667f5d6d2a34`（红底金字锦鲤桌垫）。

```bash
node tools/res-combo-test.mjs <connectionId>     # 内含复刻用例；也可用下方最小命令
```

最小命令：

```bash
curl -s -X POST http://127.0.0.1:1520/api/ai-assistant/tools/execute \
  -H "Authorization: Bearer $TOKEN" -H "Content-Type: application/json" \
  -d '{"tool":"system.design_tool.batch_start","input":{
    "connectionId":"<clientId>","count":1,"taskPreset":"custom",
    "outputKind":"independent-batch","enableAnalysisOptimization":false,"saveMode":"auto",
    "taskSource":{"kind":"inspirations",
      "inspirationIds":["7700ff58-4fa9-4ec9-8b84-667f5d6d2a34"],
      "variantsPerInspiration":1,
      "sizes":[{"width":3000,"height":1376,"label":"长款"}],
      "reportBack":true},
    "timeoutMs":900000}}'
```

| 验收点 | 标准 |
|---|---|
| 视觉分析发生 | 浏览器 console 出现 `参考图分析已经完成`（且**不是** `视觉参考图未生效`） |
| 图上文字 | **逐字保留**（参考图是「锦鲤附体」，产出主文案也必须是「锦鲤附体」） |
| 主色 | 与参考图同色系（参考图红+金 → 产出应为红/金调，**不是**蓝/绿） |
| 装饰逻辑 | 锦鲤等主体元素有呼应 |
| 不贴原图 | 产出里**不能**出现商品本体、包装、拍摄背景（键盘/鼠标/价格标签） |

**已知偏差（可接受但需记录）**：底色可能由深酒红漂移为蓝橙。参考图是电商截图，画面里的米色背景/键盘等非印花区域会干扰取色。发现偏差请记录到测试报告，这是**已知待优化项**。

### T-图片复刻

```bash
# 用 MCP replicate_from_image
curl -s -X POST .../tools/execute -d '{"tool":"system.design_tool.replicate_from_image","input":{
  "connectionId":"<clientId>",
  "imageUrl":"<图片URL>",
  "variants":1,
  "sizes":[{"width":3000,"height":1376,"label":"长款"}]}}'
```

验收：读图重建印花本身（不是贴图）、图上文字逐字保留、配色对齐。

### T-自定义贴纸复刻（HTML 基稿）

```bash
node tools/test-replicate.mjs <sourceStickerId> 2 3000 2000 "3:2"
```

| 验收点 | 标准 |
|---|---|
| 同系列 | 变体与基稿同主题、同气质、同配色家族 |
| 有差异 | 在指定扰动维度（配色/字体/构图/文案）明显不同 |
| 不是重来 | 不得换成完全不同的主题 |
| 产出数 | `variants × sizes` 张 |

`sourceStickerId` 可从 `list_resources` 取（`type: "sticker"`）。

### T-资源组合（字体/图片/技巧/文案/提示词）

```bash
node tools/res-combo-test.mjs <connectionId>
```

内含 4 个用例：

| 用例 | 组合 | 验收点 |
|---|---|---|
| **T1 字体+图片** | font + sticker | 字体真的进了 `font-family`；图片真的被引用；两者都可见 |
| **T2 字体+技巧+文案** | font + tip + sentence | 技巧的形态特征可见；文案取自资源 |
| **T3 自定义贴纸复刻** | `taskSource.kind=replicate` | 同系列 + 有扰动 |
| **T4 四资源组合** | font + image + tip + prompt | 四种资源全部被使用 |

**资源"是否真的用上"怎么验**：

1. 绑定形式：字体走 `font-family:{{font.键.family}}`，图片走 `{{image.键.url}}`
2. 看产出：字体形态与图片元素能否在成品中辨认出来
3. 冲突时按优先级：**灵感 > 提示词/技巧 > 文案**；字体/图片/贴纸**必须使用**

先盘点可用资源（拿 id）：

```bash
node tools/res-inventory.mjs <connectionId>
```

## 4. 验收标准（通用）

### 4.1 硬性（不通过即算 bug）

- [ ] 尺寸与请求完全一致
- [ ] 主文案**几何中心**在画布正中（不是主+副整体居中）
- [ ] 文字完整：不截断、不溢出、无 `ellipsis/nowrap`
- [ ] 字号：主文案单行 ≤ 画布高 26%（两行每行 ≤14%）
- [ ] 无 `vw/vh/clamp` 做字号
- [ ] 背景至少三层，无大片纯色空白
- [ ] 成功落库且 URL 可访问

### 4.2 软性（记录问题，不阻塞）

- 背景丰满度、装饰丰富度
- 配色与参考图/灵感的贴合度
- 字体气质与主题匹配度

## 5. 失败排查手册

| 症状 | 排查方向 |
|---|---|
| 所有命令失败、无响应 | 设计端没在线 → `query_design_tools`；或后端挂了 → 试 `GET /api`（404 是正常的，说明服务活着） |
| `当前设计实例正在执行其他自动制作任务` | 上一个批量没跑完；等它结束或换 clientId |
| `生成失败: 第 N 张设计 超时` | 视觉任务 22.5 分钟上限；检查是否卡在无工具调用的循环里 |
| 产出与参考图无关 | ①console 搜 `视觉参考图未生效`（视觉模型不可用）；②确认走的是带图路径；③确认 brief 没发明主题 |
| `参考图分析已经完成` 反复刷屏 | agent 读完图但没调 `canvas.addHtml`（已做催促去重，仍刷屏需查 agent 循环） |
| 渲染超时 | 字体子集化是否生效（`font-subset.ts`） |
| 画布残留旧内容 | `add-child` 的替换判断 |
| 落库了但图不对 | 打开 URL 看；再跑 `audit_canvas` 看审查结论 |
| 数据库查不到 | 确认 `userId`、时间范围；`saveMode` 是否为 `auto` |

### 5.1 有用的观测点

```bash
# 批量实时进度（必须轮询，batch_start 立即返回 progress 不带 batch）
curl -s -X POST .../tools/execute -d '{"tool":"system.design_tool.batch_get_state","input":{"connectionId":"<clientId>"}}'
# 取值：data.messages[role=tool].toolResult.data.raw.batch

# 审查当前画布
curl -s -X POST .../tools/execute -d '{"tool":"system.design_tool.audit_canvas","input":{"connectionId":"<clientId>"}}'
```

**浏览器 console 是最重要的现场**：`参考图分析已经完成`、`视觉参考图未生效`、`[Agent]` 前缀日志都在那里。

```bash
# Playwright 读 console
"$PWCLI" console | grep -E "视觉|参考图|Agent"
```
